# NetSage AI — Full Project

A complete, working AI-assisted network troubleshooting console, built to the
"NetSage AI" assignment brief: static HTML/CSS/JS frontend + Python scripts
for case management, deterministic rule-checking, and AI diagnosis.

**This project ships empty on purpose.** `data/cases.csv` contains only the
column headers — no synthetic/placeholder cases. Per the assignment, your
30+ cases must come from your own real Packet Tracer lab. Use the "+ Add
case" button in the website, or edit `data/cases.csv` directly, to add them.

## Project structure

```
netsage-ai/
  index.html                 the website
  style.css
  script.js
  data/
    cases.csv                master case dataset (edit this, or use the in-app "+ Add case" form)
    cases.json                generated from cases.csv for the website to load
    ai_results.json           generated by scripts/run_diagnosis.py — AI diagnosis per case
    rule_checker_report.json  generated by scripts/rule_checker.py — deterministic findings per case
  scripts/
    build_cases.py            edit the CASES list here to author cases in Python, then regenerate cases.csv
    csv_to_json.py            cases.csv -> cases.json (run after editing cases.csv directly)
    rule_checker.py           deterministic checks (duplicate IP, wrong mask, gateway mismatch, etc.)
    run_diagnosis.py          calls Claude for each case, saves results to ai_results.json
  prompts/
    diagnose_prompt.md        the exact system prompt + worked examples used by run_diagnosis.py
  docs/
    responsible_ai_log_template.md
    demo_script.md
```

## How the pieces fit together

1. **Author cases** — either edit `data/cases.csv` directly (simplest for pasting in
   real Packet Tracer captures), or use the website's "+ Add case" button (saved to
   your browser's local storage), or add to the `CASES` list in `scripts/build_cases.py`
   and run it to regenerate `cases.csv`.
2. **Sync cases.csv → cases.json** so the website can see CSV edits:
   ```
   python3 scripts/csv_to_json.py
   ```
3. **Run the deterministic rule checker**:
   ```
   python3 scripts/rule_checker.py
   ```
4. **Run AI diagnosis** (needs your own Anthropic API key — see below):
   ```
   export ANTHROPIC_API_KEY="sk-ant-..."
   python3 scripts/run_diagnosis.py
   ```
   This calls Claude once per case using the prompt in `prompts/diagnose_prompt.md`
   and saves everything to `data/ai_results.json`. Re-run anytime; it skips cases
   that already have a result unless you pass `--overwrite`. You can also target
   specific cases: `python3 scripts/run_diagnosis.py C001 C010`.
5. **Open the website** (see "Running locally" below), click through cases, and
   Accept / Mark edited / Reject each AI diagnosis with a note. Reviews are saved
   in your browser's local storage.
6. **Export deliverables** from the Dashboard and Responsible AI log tabs:
   "Export cases.csv" (includes anything you added via the UI), "Export reviews.json",
   and "Export Responsible AI log (.md)" — ready to hand in.

## Why AI diagnosis runs in Python, not the browser

Calling the Anthropic API directly from client-side JavaScript would require
embedding your API key in code anyone visiting the page could read — never do
this. `run_diagnosis.py` calls the API from your machine instead, and the
website just displays the saved results. This is also why `run_diagnosis.py`
has zero third-party dependencies (uses only Python's standard library) — it
should run on any machine with Python 3 installed, no `pip install` needed.

## Running locally

Browsers block `fetch()` of local files opened directly (`file://...`), so serve
the folder over local HTTP instead:

```
cd netsage-ai
python3 -m http.server 8000
```

Then open `http://localhost:8000` in your browser.

(VS Code's "Live Server" extension works too, if you prefer.)

## Publishing to GitHub Pages

1. Push this whole folder to a GitHub repository.
2. In the repo: Settings → Pages → Source → "Deploy from a branch" → `main` / `/(root)`.
3. Your site will be live at `https://YOUR-USERNAME.github.io/REPO-NAME/` within
   a minute or two.
4. Since this is a fully static site (no server needed), GitHub Pages hosts it
   exactly as-is — the AI diagnosis results baked into `data/ai_results.json`
   at the time you push will be what visitors see. Re-run `run_diagnosis.py`
   and push again any time you add new cases.

## A note on browser storage

This project uses `localStorage` for cases you add via the UI and for your
review decisions, since it's a plain static site with no backend. This works
normally in any real browser (Chrome, Firefox, Edge, Safari) once hosted or
served locally — it does **not** work if you preview this inside Claude.ai's
own artifact panel, which sandboxes and blocks browser storage APIs. Open it
in an actual browser tab (via `python3 -m http.server` or GitHub Pages) to see
persistence working correctly.
